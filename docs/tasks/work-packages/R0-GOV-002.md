## 失败路径

- 在 Product Owner 与 Architecture Lead 接受 ADR 前新增分发许可证、公开发布或把外部分发标记为允许时失败；
- 将内部访问、GitHub 可见性、文件存在或工具可下载解释为复制、修改或再分发授权时失败；
- tracked 第三方代码、数据、archive 或生成物缺少精确来源、版本/日期、完整性、许可证结论、用途或 owner 时失败；
- 把 SPDX `NONE` 当作许可证，或把 `NOASSERTION` 项标记为可外部分发时失败；
- 使用 `LicenseRef-*` 却未保存对应自定义许可证文本与稳定标识时失败；
- 把 Eigen 3.4.0 的“主要 MPL-2.0”简化为全部文件单一许可证，或未对实际 include 范围和 LGPL/BSD 文件做复核时失败；
- 把 w64devkit 顶层源码许可证当作其全部捆绑组件和 runtime 的单一许可证时失败；
- 冻结 Legacy archive 的 hash、文件数、license scan 或 evidence-only 状态漂移时失败；
- 生成 Artifact、报告或导出包丢失上游数据/代码/工具的许可证、分类、完整性或 lineage 时失败；
- inventory 使用未知 category/classification/integrity kind，或 category 与 classification 不匹配时失败；
- generated evidence 缺少上游 lineage、引用不存在的 parent、完整性 identity 为空，或把 `blocked-*` 降为 `not-redistributed` 时失败；
- inventory 条目集合、顺序、词表、owner/purpose/version/scope/source/evidence/lineage 等完整语义投影漂移时失败；
- 本地 source 或 license evidence locator 使用绝对路径、转义、percent encoding、大小写别名、symlink、目录、未跟踪或空文件时失败；
- executable scientific fixture 缺失 sidecar、manifest/fact binding、来源 raw hash、units/frames/time、比较引用、独立性依据、权利 lineage 或授权 actor 时失败；
- 同源双实现被写成科学来源独立确认、sidecar 引用 Legacy 作为无关科学来源、修改已接受 v1 schema、出现产品/runtime/public consumer，或提前进入 `scientifically-accepted` 时失败；
- 外部导出未完成敏感信息、访问权限、许可证兼容性、notice/source 义务和批准记录检查时失败；
- 修改 `reference/legacy/`、为产品目录引入新依赖或把治理 inventory 当作公共 runtime schema 时失败。
