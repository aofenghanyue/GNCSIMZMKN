## 分类纪律

- Preserve/Fix/Retire 是迁移处置；五类 difference policy 是处置理由，两者不得混成一个自由文本字段；
- 一条 oracle 可包含多个事实，分类必须落到事实粒度，并汇总出 oracle 级处置；
- 当前文档中的分类全部是候选，不代表 Validation Lead 或 Scientific Authority 批准；
- 没有已批准的 `Fix`。新发现的疑似缺陷先记为 `NeedsDecision`，附 defect id、影响和独立证据，再由有权 owner 决定；
- `NeedsDecision` 不能伪装成容差或 warning；它阻断对应 target 的迁移验收；
- priority 数值、注册顺序、provider 名称/RTTI、CSV column order、free-text exception 和 old Mission shape 默认属于 `AccidentalStructure`，不得进入 preserved expected facts。

## 误报与漏报失败路径

- 只解析 `simulator.hpp` 并复制控制流，不能替代运行时 trace；
- 只复跑现有 CTest 并引用 exit 0，不能证明 bundle 带输入 hash、分类和完整 provenance；
- 只比较最终 CSV，会把 phase、candidate/commit 和 terminal ordering 的错误漏掉；
- 用原始 CSV byte equality 当唯一科学证据，会错误锁定列序、格式、输出目录和非语义文本；
- 用现有 test tolerance 直接冻结所有 target tolerance，会越过 `R0-SCI-003` 的科学审查；
- probe 自己改变被观察状态、注册顺序或 publish/commit 调度，会使 oracle 失真；
- 对临时改写过的 Legacy 源码生成“canonical”证据，会破坏冻结来源身份；
- Legacy 缺少 `RunOutcome` 或 deterministic target CaseId 时填造占位值，会把目标 fixture 冒充旧行为事实；
- 新建未走 ADR 的公共 schema，或在未闭合 R0-SPEC-001 前改变 manifest version，会破坏单一契约 authority。
