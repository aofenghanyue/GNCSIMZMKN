## 准备结论

`REF-YYZ-001` 当前只是 `specification_only` seed，不能证明 YYZ 6DoF 科学模型、轨迹、终止指标或 target runtime 已经正确。审计确认必须把三类事实分成互不替代的证据 lane：

1. **Target normative conformance**：00A 的 Mission、Plan、transaction、Observation、diagnostic 与 lineage 示例；
2. **Frozen Legacy behavior**：冻结 archive 中 2 s YYZ 模板的实际运行事实；
3. **Independent scientific reference**：不调用 Legacy Simulator 或未来 Session 的公式、轨迹、终止和 tolerance 真值。

00A 的 30 s / 100 Hz / 20 Hz altitude-hold 例子与冻结 Legacy 的 2 s / 50 Hz / 10 Hz trajectory-template 不是同一个实验；00A 和 15 §4 对 guidance 频率也分别给出 20 Hz 与 10 Hz。00A 在 tick 2500 的高度、俯仰、升降舵数值及“俯仰超调 6.4%”没有当前独立来源，短写 `sha256:91b7`、`sha256:3d0a` 等也不是完整内容哈希。它们在 Scientific Authority 关闭来源决策前不能进入科学 expected。

本准备包把冲突、决策、公式覆盖、机器 fixture、Legacy 捕获、独立 reference、差异分类和失败矩阵收敛到可领取设计。详细设计见 [REF-YYZ-001 reference bundle 设计](../../quality/yyz-reference-bundle-design.md)。本切片没有修改 backlog、fixture、schema、产品代码或冻结 Legacy，不能作为 `R0-SCI-003` 完成或 G1 通过证据。

## 依赖关闭后的实施切片

1. 指派 assignee/reviewer，将 backlog 从 `planned` 改为 `in_progress`；
2. 关闭 `YYZ-DEC-001`–`012`，把批准 ref 绑定到每条模型、输入、tolerance 和分类；
3. 建立 target conformance lane：先把 00A source、plan、step、observation、diagnostic、manifest/lineage 变为 machine-valid，但将尚无 runtime 的断言标成 `target_pending`；
4. 建立 pure-formula lane：每个 kernel 的输入、intermediate、输出、unit/frame/time relation、domain 与 independent expected；
5. 建立 independent trajectory lane：从批准 source/assets 独立生成初值、逐 tick/抽样轨迹、terminal、metric 与 dt-convergence；
6. 从冻结 ZIP 创建全新隔离 workspace，按 `R0-LEG-002` 重捕获 YYZ raw output 两次，保存输入/环境/命令/hash；
7. 通过 CSV header 生成 semantic sidecar，比较 Legacy 与 approved target/reference 的同义字段；旧列序、节点数和 free-text 不进入 truth；
8. 生成 tolerance/difference report；每项差异为 approved Preserve/Fix/Retire/NeedsDecision 和独立 rationale，不允许未解释 pass；
9. 让同一生产 validator 执行正常 bundle 与 mutation matrix；
10. 接入 CTest/repository verification，在固定 Windows/Linux profiles 运行并保存 evidence；
11. Scientific Authority、Validation Lead、Runtime Numerics Lead、Model SDK Lead 与相关 Architecture owner 审查后转 `review`。
