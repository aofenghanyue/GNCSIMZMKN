## 准备结论

仓库已有 `REF-MINIMAL-3DOF-001` 的 specification-only manifest，但只有“轨迹”和“失败”两条占位事实，没有模型方程、初值、语义字段、解析轨迹、termination、dt convergence、独立实现或 evidence hash。它当前不能证明 G1 所需的最小 3DoF 科学 oracle。

准备设计采用单一平移模型 `r_dot = v`、`v_dot = a0 - lambda*v`。`lambda=0` 有常加速度闭式解，`lambda>0` 有线性阻尼闭式解；二者都不依赖 Legacy Simulator。四个互补案例分别验证闭式轨迹、RK4 四阶收敛、ExactGrid 上的终止事实，以及 RK stage 领域失败时 candidate 不提交。详细模型、数值输入和证据设计见[最小 3DoF 独立参考设计](../../quality/minimal-3dof-reference-design.md)。

本准备包没有修改 backlog、fixture、schema、产品源码或 Legacy，不能作为 `R0-SCI-002` 完成或 G1 通过的证据。

## 误报与漏报失败路径

- 只做常加速度 case 会让 RK4 在该多项式上近乎/完全精确，无法证明实现具有四阶收敛；
- 只比较最终状态会漏掉中间 tick、时间生成、terminal 和 candidate failure；
- 把 position 与 velocity 混进一个有量纲最大误差，会隐藏某一状态族的退化；
- 用 C++ solver 生成 expected 再由同一 C++ solver 自验，会形成共同实现错误；
- Python 解析和 C++ probe 复制同一段 RK4，而没有闭式 truth，会降低独立性；
- 以 CSV byte equality 作为 truth 会锁定编码、列序和格式化误差；
- 用非网格 crossing 却未声明 root/StopBefore/StopAfter policy，会把时间决策混入科学 reference；
- 通过放宽 tolerance 隐藏阶数下降、NaN、wrong sign 或 off-by-one，会产生伪 pass；
- 把 fixture-local status 当作未来 `DiagnosticCode`/`RunOutcome` 公共契约，会越过 R1–R3；
- 在依赖 review 未关闭时修改 fixture/schema/backlog，会绕过任务门禁。
