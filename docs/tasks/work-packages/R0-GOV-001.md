## 失败路径

- required role 缺少 assignee 或 reviewer 时，把任务/G0/G1 标记完成会失败；
- assignee 与 reviewer 相同，或 Scientific Authority 与 Architecture Lead 的高风险签字身份相同会失败；
- 未登记的 Codex/AI 别名、占位符、推测姓名、邮箱或平台账号会失败；actor 名称不同但 task binding 相同也不能形成 accountable review；
- ADR 在 Product Owner 与 Architecture Lead 未具名签字时变为 `Accepted` 会失败；
- 把 Proposed/candidate profile 描述为已支持、已发布或兼容性承诺会失败；
- `CMAKE_CXX_STANDARD`、project manifest 或矩阵偏离 C++17 时失败；
- preset schema 所需 CMake 版本高于声明 minimum，或 dev/release preset 语义漂移时失败；
- CI 使用 `ubuntu-latest`、`windows-latest`、preview runner、浮动 action tag 或未记录工具版本时失败；
- candidate-primary profile 缺少 x64、编译器 family/range、CMake/generator、PowerShell、Python、warnings-as-errors 或 evidence 时失败；
- 将 w64devkit/Legacy GCC 复现环境提升为新产品支持工具链时失败；
- 将 Clang、macOS、ARM、MinGW product build、动态 ABI 或 Python wheel 声明为 qualified 而没有测试证据时失败；
- hosted runner 的每周 patch 漂移未记录 exact environment identity 时失败；
- 修改产品模块、冻结 Legacy 或为验证下载/提交未经 provenance 审查的工具时失败。

## 验收与证据

- 9 个角色均有 assignee/reviewer 字段，8 个 required role 均解析到已授权且相互独立的 actor/task 配对；
- Proposed matrix 只有两个 candidate-primary profile：Windows x64/MSVC 19.5x 和 Ubuntu 24.04 x64/GCC 13.x；
- CMake 3.20 文档可表达当前 configure/build/test presets，`CMakePresets.json` 使用 schema version 2；
- CI 使用 `ubuntu-24.04` 与 `windows-2025-vs2026`，checkout 固定到已审查 v6.0.2 commit，不使用 `*-latest`；
- CI 在 Release、warnings-as-errors 下运行全部 CTest 和 repository verification，并输出 runner/compiler/CMake/Ninja/PowerShell/Python identity；
- validator 区分配置一致性、ADR disposition 与 Hosted CI 状态，不伪造整体 gate success；
- mutation suite 至少拒绝缺 reviewer、同 actor/task 自审、Science/Architecture 共用 actor/task、缺授权来源或 R0 scope、机器身份伪装、未登记 alias、Accepted 无完整角色、无法读取 reviewed commit 的浅克隆、preset/CMake 不一致、latest runner、未限定 compiler、提升 Legacy toolchain 和 `codex-r0-*` 虚拟席位；
- Windows MSVC Debug/Release、Linux GCC smoke、repository verification、全量 bootstrap 与 `git diff --check` 通过。
